## Введение

Tokamak Analysis Platform -- ИИ-система для анализа экспериментальных данных токамаков, разработанная в НИЯУ МИФИ. Платформа предназначена для исследователей, инженеров и администраторов, работающих с данными плазменных экспериментов.

**Основные возможности:**
- Загрузка экспериментальных данных из архива FAIR-MAST (11 573 выстрела)
- Препроцессинг и визуализация временных рядов (Plotly.js)
- Классификация стабильности плазмы (stable / unstable)
- Предсказание срывов (disruption prediction) с вероятностным окном предупреждения
- Обучение ML-моделей через веб-интерфейс с отслеживанием прогресса
- Экспорт данных в CSV и JSON
- Управление пользователями и ролями (RBAC)

**Для кого эта платформа:**
- **Исследователи** (роль `researcher`) -- загрузка данных, визуализация, анализ
- **Инженеры** (роль `engineer`) -- обучение моделей, управление версиями
- **Администраторы** (роль `admin`) -- управление пользователями, полный доступ

## Регистрация и вход

### Регистрация

1. Откройте платформу в браузере (по умолчанию `http://localhost`)
2. Нажмите **"Регистрация"** на странице входа
3. Заполните форму:
   - **Email** -- будет использоваться для входа
   - **Пароль** -- минимум 8 символов
   - **Полное имя** -- ваше ФИО
   - **Роль** -- по умолчанию `researcher`
   - **Согласие на обработку ПДн** -- обязательное поле (152-ФЗ)
4. Нажмите **"Зарегистрироваться"**

![Регистрация](images/register.png)

### Вход в систему

1. На странице входа введите email и пароль
2. Нажмите **"Войти"**
3. Система выдаст JWT-токены:
   - **Access token** -- действует 15 минут
   - **Refresh token** -- действует 7 дней (обновляется автоматически)

![Вход в систему](images/login.png)

### Как работает аутентификация

Платформа использует JWT (JSON Web Tokens). После входа access token автоматически добавляется ко всем запросам. Когда access token истекает, система прозрачно обновляет его через refresh token -- вам не нужно входить заново.

Если refresh token тоже истек (через 7 дней без активности), потребуется повторный вход.

## Загрузка экспериментальных данных

### Что такое shot_id

Каждый плазменный эксперимент (выстрел) в архиве FAIR-MAST имеет уникальный числовой идентификатор -- `shot_id`. Архив содержит данные 11 573 выстрелов токамака MAST (Mega Ampere Spherical Tokamak, Великобритания).

### Загрузка одного выстрела

1. Перейдите на страницу **"Эксперименты"**
2. В поле **"Shot ID"** введите номер выстрела (например, `30420`)
3. Нажмите **"Загрузить"**
4. Система загрузит данные из FAIR-MAST S3 (анонимный доступ), выполнит препроцессинг (нормализация, ресемплинг) и сохранит результат

![Загрузка данных](images/load-shot.png)

### Пакетная загрузка

Для загрузки нескольких выстрелов одновременно используйте пакетную загрузку:
1. Укажите список shot_id (до 50 штук)
2. Система загрузит их параллельно
3. Результат покажет успешно загруженные эксперименты и ошибки (если были)

### Источник данных: FAIR-MAST

Данные загружаются из S3-хранилища FAIR-MAST:
- **Endpoint**: `https://s3.echo.stfc.ac.uk`
- **Bucket**: `mast`
- **Доступ**: анонимный (учетные данные не требуются)

Каждый выстрел содержит набор сигналов (временных рядов): ток плазмы, плотность, температура, магнитные поля и другие параметры.

## Визуализация временных рядов

После загрузки эксперимента вы можете просмотреть все временные ряды на интерактивных графиках.

### Просмотр графиков

1. Перейдите на страницу эксперимента (нажмите на эксперимент в списке)
2. Графики временных рядов отображаются с помощью **Plotly.js**
3. Для каждого сигнала показаны:
   - Название параметра
   - Единицы измерения
   - Временная ось (мс)
   - Значения сигнала

![Визуализация временных рядов](images/timeseries-chart.png)

### Интерактивные возможности

Графики Plotly.js поддерживают:
- **Масштабирование** -- выделите область мышью для приближения
- **Панорамирование** -- зажмите и перетащите для прокрутки
- **Hover** -- наведите курсор для просмотра точных значений
- **Сброс масштаба** -- двойной клик или кнопка на панели инструментов
- **Скачивание** -- сохранение графика как PNG

## Классификация стабильности плазмы

Классификация определяет, является ли плазменный разряд стабильным или нестабильным.

### Выполнение классификации

1. Откройте загруженный эксперимент
2. На панели **"Предсказания"** нажмите **"Классифицировать"**
3. Система отправит данные в ML-сервис и вернет результат:
   - **Метка**: `stable` или `unstable`
   - **Уверенность**: от 0.0 до 1.0 (чем выше, тем увереннее модель)
   - **Время инференса**: в миллисекундах

![Классификация стабильности](images/classification.png)

### Выбор модели

По умолчанию используется последняя активная модель для задачи классификации. Вы можете указать конкретную модель по `model_id`, если хотите сравнить результаты разных моделей.

### Пакетная классификация

Для классификации нескольких экспериментов одновременно:
1. Выберите эксперименты (до 50 штук)
2. Нажмите **"Пакетная классификация"**
3. Результаты покажут метку и уверенность для каждого эксперимента

## Предсказание срывов

Предсказание срывов (disruption prediction) -- ключевая функция платформы. Модель анализирует временные ряды и выдает вероятность срыва в каждый момент времени.

### Выполнение предсказания

1. Откройте загруженный эксперимент
2. На панели **"Предсказания"** нажмите **"Предсказать срыв"**
3. Результат содержит:
   - **Временной ряд вероятностей** -- графически показывает вероятность срыва
   - **Предупреждение** -- выдается, если вероятность превысила порог
   - **Время предупреждения** -- за сколько мс до потенциального срыва система предупредила
   - **Рекомендации** -- автоматически сгенерированные рекомендации по действиям

![Предсказание срывов](images/disruption-prediction.png)

### Настройка порога срабатывания

Порог (threshold) определяет, при какой вероятности система выдает предупреждение:
- **По умолчанию**: 0.7 (70%)
- **Настройка**: перейдите в настройки и измените значение от 0.0 до 1.0
- **Низкий порог** (например, 0.3) -- больше предупреждений, выше чувствительность, больше ложных срабатываний
- **Высокий порог** (например, 0.9) -- меньше предупреждений, ниже чувствительность, меньше ложных срабатываний

### Рекомендации

При предсказании срыва система автоматически генерирует рекомендации:
- Уровень риска (низкий / средний / высокий / критический)
- Предлагаемые действия оператора
- Оценка времени до потенциального срыва

## Обучение моделей

Платформа поддерживает обучение трех типов ML-моделей через веб-интерфейс.

### Доступные модели

| Модель | Тип | Назначение | Латентность |
|--------|-----|-----------|-------------|
| **Random Forest** | Baseline | Классификация стабильности | до 5 мс (CPU) |
| **bi-LSTM+Attention** | Основная | Классификация + предсказание срывов | до 30 мс (GPU) |
| **Transformer** | Экспериментальная | SOTA предсказание срывов | до 50 мс (GPU) |

### Запуск обучения

1. Перейдите на страницу **"Обучение моделей"**
2. Выберите параметры:
   - **Тип модели**: `random_forest`, `lstm_attention` или `transformer`
   - **Задача**: `classification` или `disruption_prediction`
   - **Гиперпараметры** (опционально) -- если не указаны, используются значения по умолчанию из конфигурации
   - **Shot IDs для обучения** (опционально) -- если не указаны, используется весь доступный датасет
3. Нажмите **"Начать обучение"**

![Обучение модели](images/training.png)

### Гиперпараметры

Конфигурации моделей по умолчанию хранятся в файлах `configs/*.yml`:

**Random Forest** (`configs/rf.yml`):
- `n_estimators` -- количество деревьев (по умолчанию 100)
- `max_depth` -- максимальная глубина дерева
- `min_samples_split` -- минимум примеров для разделения

**bi-LSTM+Attention** (`configs/lstm.yml`):
- `hidden_size` -- размер скрытого состояния
- `num_layers` -- количество слоев LSTM
- `attention_heads` -- количество голов внимания
- `learning_rate` -- скорость обучения
- `epochs` -- количество эпох

**Transformer** (`configs/transformer.yml`):
- `d_model` -- размерность модели
- `nhead` -- количество голов внимания
- `num_layers` -- количество слоев
- `learning_rate` -- скорость обучения
- `epochs` -- количество эпох

При запуске обучения вы можете переопределить любые гиперпараметры.

### Процесс обучения

Обучение выполняется асинхронно через Celery:
1. Задача ставится в очередь Redis
2. Celery Worker получает задачу и отправляет её в ML-сервис
3. ML-сервис обучает модель и сохраняет артефакты в MinIO
4. Метрики записываются в базу данных

Вы можете отслеживать прогресс в реальном времени через polling статуса.

## Просмотр результатов обучения

### Список запусков обучения

На странице **"Обучение"** отображается список всех ваших запусков:
- **Статус**: `queued` -> `running` -> `completed` / `failed`
- **Прогресс**: от 0% до 100%
- **Метрики**: accuracy, AUC-ROC, F1-score и другие
- **Гиперпараметры**: использованные значения
- **Время**: начало, окончание, длительность

### Детали запуска

Нажмите на запуск для просмотра деталей:
- Полные метрики обучения
- Использованные гиперпараметры
- ID Celery-задачи (для отладки)

### Управление версиями моделей

Каждое обучение создает новую версию модели. Вы можете:
- Просмотреть все версии конкретной модели
- Активировать определенную версию (rollback)
- Сравнить метрики разных версий

## Экспорт данных

### Экспорт эксперимента

Данные эксперимента можно экспортировать в двух форматах:

**CSV**:
1. Откройте эксперимент
2. Нажмите **"Экспорт"** -> **"CSV"**
3. Скачается файл `shot_<shot_id>.csv` с колонками: `parameter`, `timestamp`, `value`, `units`

**JSON**:
1. Откройте эксперимент
2. Нажмите **"Экспорт"** -> **"JSON"**
3. Скачается файл `shot_<shot_id>.json` с полной структурой данных

### Экспорт персональных данных

В соответствии с 152-ФЗ вы можете экспортировать все свои персональные данные:
1. Перейдите в настройки профиля
2. Нажмите **"Экспорт данных"**
3. Будет скачан JSON с вашим профилем, экспериментами, предсказаниями и запусками обучения

## Администрирование

Функции администрирования доступны только пользователям с ролью `admin`.

### Управление пользователями

1. Перейдите в раздел **"Администрирование"** -> **"Пользователи"**
2. Отображается список всех пользователей с информацией:
   - Email, имя, роль, статус (активен/деактивирован)

![Администрирование](images/admin-users.png)

### Изменение роли пользователя

1. Найдите пользователя в списке
2. Выберите новую роль: `researcher`, `engineer` или `admin`
3. Подтвердите изменение

**Роли и права:**
| Действие | Researcher | Engineer | Admin |
|----------|-----------|----------|-------|
| Загрузка данных | + | + | + |
| Визуализация | + | + | + |
| Классификация | + | + | + |
| Предсказание срывов | + | + | + |
| Обучение моделей | + | + | + |
| Управление пользователями | -- | -- | + |

### Деактивация пользователя

1. Найдите пользователя в списке
2. Нажмите **"Деактивировать"**
3. Пользователь потеряет возможность входа в систему

> Администратор не может деактивировать свой собственный аккаунт.

### Удаление аккаунта

Пользователь может самостоятельно удалить свой аккаунт (152-ФЗ, ст. 21):
1. Перейдите в настройки профиля
2. Нажмите **"Удалить аккаунт"**
3. Все связанные данные (эксперименты, предсказания, запуски, аудит-логи) будут удалены
